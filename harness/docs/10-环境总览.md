## 目标器件与开发板（详见 `targets/F280039C.json`）

- **TMS320F280039C**：C28x @120MHz（FPU32 + TMU + VCRC）+ CLA @120MHz，LQFP-100。
- Flash `384KB`（192KW，3 × 128KB bank）：0x080000 / 0x090000 / 0x0A0000（链接器用 22 位地址形式）。
- SRAM `69KB`（34.5KW）：M0/M1 + LS0–LS7 + GS0–GS3。
- **LAUNCHXL-F280039C 板级事实**（TI SPRUJ31 §3.1.3）：
  - 用户 LED：**LED4（红）= GPIO20**，**LED5（绿）= GPIO22**。
  - LED 经 SN74LVC2G07DBVR 驱动，**低电平点亮**：GPIO 写 `0` = 亮，写 `1` = 灭。
  - 板载 **XDS110**，走 **cJTAG (1149.7) 2-pin advanced**。
  - XDS110 虚拟 COM：SCIA TX=GPIO29 / RX=GPIO28，115200-8N1。

## C28x 字地址模型（本环境第一条硬事实）

C28x 工具链的**所有地址都是 16 位字地址**：链接器 `.cmd` origin、map 文件的地址与 size、
反汇编、DSS `readWord`、`PC`/`XARn` 全部一致；`sizeof(uint32_t)=2 字`，`*+XARn[N]` 位移为 N 字，
`memory.readWord()` 只返回一个 16 位字（32 位寄存器要读两个字拼接）。
完整证据链、GPIO 寄存器真实布局（字地址表）与踩坑教训见
`40-烧录与调试手册.md` 与 `adr/0002-C28x字地址模型与GPIO实证.md`。

## 环境修复备忘（踩坑记录）

- **C 盘没有 `C:\ti`**：本机所有 TI 工具链都在 `D:\ti\ccs2101`。任何脚本/文档引用路径时
  不得使用默认 `C:\ti` 假设（已在本机 doctor.ps1 里按多盘符搜索，避免硬编码）。
- **LaunchPad 必须用 cJTAG 2-pin 配置**：ccxml 里 `SWD Mode Settings` = `4`
  （cJTAG 1149.7 2-pin advanced）。用标准 4 线 JTAG 配置会报
  `IcePick_C_0: Error connecting to the target: (Error -2131 @ 0x0)`——
  C2000Ware 官方 `TMS320F280039C_LaunchPad.ccxml` 就是这个配置，直接取用即可。
  备选排查：把 XDS110 TCLK 从 14MHz 降到 5.5MHz（`Select TCK Setting` = `4`）。
- **C28x 汇编器不支持 C 风格注释**：`/* ... */` 会被报
  `[E0002] Invalid mnemonic specification`（注释只能是 `;` 或第 1 列 `*`）。
  C2000Ware 26.01 自带的 FreeRTOS `portasm.asm`（development 分支）就有这个问题。
  本环境默认**不依赖 FreeRTOS**，绕开该坑；若后续引入 RTOS，先处理该文件。
- **SDK 与 projectspec 的编译器版本可能不一致**：官方 projectspec 标注
  `cgtVersion=22.6.3.LTS`，本机实际为 `25.11.1.LTS`。第三方（非 TI 编写）源码
  在新工具链下可能暴露语法/语法兼容问题。
- **offline 复现构建错误**：CCS 之外可用
  `gmake.exe -C projects\<proj>\<BuildDir> -k all` 复现（无需 IDE 打开）。
- **GPIO35–38 是 JTAG 引脚**：误配成 GPIO 会导致 JTAG 永久失连，`AGENTS.md` §3 列为红线。
- **C28x 是字地址模型**（2026-10-17 实证）：map size 列、`*+XARn[N]`、DSS `readWord` 全是
  16 位字为单位；`sizeof(uint32_t)=2 字`。曾据此误判"driverlib GPIO 寻址有 2× bug"，
  实际 driverlib 完全正确——不要试图绕开 driverlib 直接写寄存器。详见 ADR 0002。
- **DSS `readWord` 只有 16 位**：32 位外设寄存器（如 GPADAT@0x7F00，LED 位在**高字 0x7F01**）
  必须读两个字再拼接；只读低字会导致 H5 假 FAIL（2026-10-17 已修复 `hil_test.js`）。
- **C2000 上拉默认关闭**：GPAPUD 复位默认全 1（1=禁止上拉），未配置引脚是悬空输入，
  GPADAT 低字会拾取噪声（随流水灯节拍翻转的 0x3FFF/0x0 等），不是固件行为；
  判读 LED 看 GPADAT 高字 0x7F01 或 GPADAT_R@0x7F80。
- **符号断点可能回退 AET**：`breakpoint.add(symbol)` 偶报 `Error -1066` 后自动改用
  AET（ERAD）断点，功能等价，可忽略。
- **DSS 会话必须先关 AutoRunToLabelOnRestart 并 `GEL_MapOff()`**：否则 loadProgram 后
  跳到 main（跳过 wd_disable → 看门狗死循环）且外设帧读不到（0x20000）。
- **HIL 串口窗口要够长**：`run-hil.ps1 -SerialSeconds` 默认 90s，必须覆盖 dss.bat 启动 +
  连接 + 烧录（20-60s）；banner 出现在固件首次运行与 H6 重引导两次。
- **gmake 在 Windows 用 cmd.exe 作 shell**：Makefile 里不能用 `mkdir -p` / `rm -rf`，
  只能 `if not exist ... mkdir` / `rmdir /s /q`（参考工程 Makefile 已按此编写）。
- **含中文的 .ps1 必须存为 UTF-8 with BOM**：PowerShell 5.1 对无 BOM 的 UTF-8 中文脚本
  会乱码甚至解析失败；本环境所有脚本均带 BOM，新增/修改脚本时保持。
- **C28x 没有 8 位类型**：`char` 是 16 位（`CHAR_BIT=16`），`stdint.h` 不定义
  `uint8_t`/`int8_t`；字节级字段一律用 `uint16_t`（`sizeof(uint32_t)=2`）。
  写跨平台代码时禁止假设 `sizeof(char)==1` 的字节语义。
- **driverlib 开 `--define=DEBUG` 后断言需要 `__error__`**：ASSERT 失败会跳转到应用
  未定义的 `__error__` 符号；工程必须自带实现（参考工程 `source/board_error.c`，
  进 `ESTOP0` 停住），否则链接期才发现。
- **loadti 需要 `__c_args__`（错误码 4011）**：loadti 内部以 `loadProgram(file, argv)`
  加载，镜像必须定义 `__c_args__`（Makefile LDFLAGS `--args=0x200`，2026-10-17 已修）；
  HIL 的 `loadProgram(file)` 不带 argv，不受影响。详见 ADR 0004。
- **`.TI.ramfunc` 启动即重定位**：driverlib 的 `SysCtl_delay()` 身在 `.TI.ramfunc`
  （LOAD=flash / RUN=RAMLS0），C 运行库不做段拷贝——不先 memcpy 就调时钟 API 会
  ITRAP→看门狗复位（启动几毫秒即死）。启动顺序与破案证据见 `40-烧录与调试手册.md`
  "固件启动顺序"节与 ADR 0003。
