# ADR 0002 · C28x 字地址模型与 GPIO 寄存器实证：driverlib 寻址无罪，H5 失败为测试侧 bug

- 状态：已接受
- 日期：2026-10-17
- 决策者：f280039c-harness 项目

## 背景

2026-10-17 HIL 运行出现 `H5-polarity@sample0 (led4On=true led5On=true)` 失败，同时
GPADAT 采样值 0x3FFF/0x0 交替无法解释。排查过程中先后出现两个互相矛盾的假设：
(a) "driverlib `GPIO_setPinConfig` 存在字节加法 2× bug，需绕过 driverlib 直接写寄存器"；
(b) "C28x 是真实字节地址模型，map/反汇编/设备头各说各话"。
在绕开 driverlib 之前，必须用实证把地址模型钉死——否则后续所有寄存器级工作都会建在沙上。

## 决策

1. **C28x 全链路采用 16 位字地址模型**：编译器常量、链接器 `.cmd` origin、map 文件的
   地址**与 size**、反汇编、DSS `memory.readWord()`、`PC`/`XARn` 一律为字地址；
   `sizeof(uint32_t)=2 字`，`*+XARn[N]` 位移为 N 字，`readWord()` 只返回一个 16 位字。
2. **不绕过 driverlib**：实证表明 driverlib GPIO 寻址完全正确，继续作为唯一 GPIO 操作路径
   （与 ADR 0001 决策 2/4 一致）。
3. **HIL 判读规则**：DSS 脚本读 32 位外设寄存器必须读全两个字再拼接；判读 LED 只认
   GPADAT 高字 0x7F01（或 GPADAT_R@0x7F80），不读低字 0x7F00（未用引脚悬空噪声）。
4. **知识落盘**：字地址模型 + GPIO 寄存器字地址表写入 `harness/docs/40-烧录与调试手册.md` 与本 ADR；
   `targets/F280039C.json` 增加 `address_model` / `gpio_registers_word_addresses` 字段。

## 证据链（五方交叉验证，2026-10-17）

| # | 证据 | 结论 |
|---|---|---|
| 1 | 链接脚本 `FLASH_BANK0_SEC4 origin = 0x84000` ↔ map `.const@0x84000` | 链接器字地址 |
| 2 | `led_hw_channels`（`{u32;u32;}[2]` = 16 字节）map size = `0x08` = 8 字 | map size 列为字 |
| 3 | 反汇编 `led_hw_apply`：`MOVL XAR4,#0x084432` 与 map 地址一致 | 编译器常量字地址 |
| 4 | DSS `readWord(0, 0x84432)` = `0x0014/0x0800/0x0016/0x0C00` | flash 常量表 pin=20/22、cfg=0x00080800/0x00080C00，与源码一致 |
| 5 | diag15 断点差分：`GPIO_writePin` 写 `*+XAR4[2]`(0x7F02)/`*+XAR4[4]`(0x7F04)，终态 GPADAT hi=0x3144、GPADAT_R hi=0x0040、GPADIR hi=0x2050、GPAMUX2 hi=0x0500 | 落点与设备头结构体字偏移逐一相等；终态 LED4 亮/LED5 灭/SCIA 复用，与设计一致 |

GPIO 寄存器字地址表（GPA/Bank B=+0x40 字；数据块 bank 步长 8 字）：
GPAMUX1=0x7C06、GPAMUX2=0x7C08、GPADIR=0x7C0A、GPAPUD=0x7C0C、GPAINV=0x7C10、
GPAODR=0x7C12、GPAGMUX1=0x7C20、GPAGMUX2=0x7C22、GPADAT=0x7F00(32b)、GPASET=0x7F02、
GPACLEAR=0x7F04、GPATOGGLE=0x7F06、GPBDAT=0x7F08、GPADAT_R=0x7F80(32b)。
完整表见 `harness/docs/40-烧录与调试手册.md`。

## 备选与理由

| 备选 | 落选原因 |
|---|---|
| 绕过 driverlib，工程侧直接写 GPIO 寄存器 | 基于错误前提（2× bug 不存在）；会引入第二套寄存器真相，违反 AGENTS.md §4 |
| 按"真实字节地址"模型重写所有地址推导 | 与五方证据全部矛盾；map size 0x08（16 字节结构体）在字节模型下无解 |
| 接受 H5 FAIL，改固件迁就测试（如把 LED 挪到 GPIO0-15） | 治标不治本；固件行为本就正确，错的是 16 位读法 |

## 后果

- H5 假 FAIL 根因消除：`hil_test.js` 改为双字拼接 + GPADAT_R 交叉校验 + 平均周期节拍测量
  （采样远快于 200ms，量化误差被平均掉；该周期同时证明 SYSCLK=120MHz）。
- 悬空引脚噪声（GPADAT 低字 0x3FFF/0x0 翻转、GPBDAT 低字随 JTAG 扫描变化）有了确定解释：
  C2000 上拉默认关闭（GPAPUD 复位全 1），未用引脚悬空；判读只认目标引脚所在字。
- 成本：所有 C28x 文档/脚本必须显式区分"字"与"真实字节"；`readWord` 类 API 用后即弃
  （32 位寄存器一律双字读取）。
- 触发复审：若升级编译器/C2000Ware 后 map size 语义变化，或更换 C28x 以外内核
  （如 ARM/CLA 独立编址），需重跑五方对账并更新本 ADR。
