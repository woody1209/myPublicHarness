# ADR 0007 · 头文件依赖与陈旧镜像（gmake + cl2000）

- 状态：已接受
- 日期：2026-10-18
- 决策者：woodywu（由故障注入实验暴露，反汇编取证裁决）

## 背景

执行 REQ-004 的故障注入验证时，把 `LED_PATTERN_REF_FNV1A` 改成 `0xDEADBEEFU`，
期望上板自检失败并进入 fail-safe。结果：

- `gmake` 打印了 `'C2000 Compiler - building file: "source/self_test.c"'`
- 但 `CPU1_FLASH/self_test.obj` 时间戳**未变**（仍是 23:14:23）
- 反汇编 `.out`：`MOV AH, #0x436f` —— **镜像里还是旧常量**
- 于是 HIL 报 `HIL RESULT: PASS`，产生一次**假 PASS**

即：改了头文件，产物却是陈旧的，而构建过程看起来完全正常。

## 根因（两层）

1. **`.d` 文件生成了却没人读。** Makefile 用 `--preproc_dependency=...` 让 cl2000
   生成依赖文件，但全文没有 `-include $(DEPS)`，gmake 不知道头文件是前置条件。
2. **即便加了 `-include` 也不生效。** cl2000 生成的 `.d` 内容使用**反斜杠**路径：
   ```
   CPU1_FLASH\self_test.obj: source\led_pattern.h
   ```
   而 Makefile 的模式规则目标是**正斜杠** `CPU1_FLASH/self_test.obj`。
   gmake 视为两个不同目标，`-include` 静默失效（实测：加了 `-include` 后
   `self_test.obj` 仍未重编）。

## 决策

不依赖 `.d`，直接把本地头文件作为 `.obj` 的显式前置条件：

```makefile
HEADERS := $(wildcard $(SOURCE_DIR)/*.h)

$(BUILD_DIR)/%.obj: $(SOURCE_DIR)/%.c $(HEADERS) | dirs
```

- 与路径分隔符无关，确定性生效；
- 本项目源文件 < 10 个，多出来的重编成本可忽略；
- 正确性优先于构建速度 —— 陈旧镜像会制造假 PASS，这是最坏的失败模式。

## 证据

| 项 | 修复前 | 修复后 |
|---|---|---|
| 改 `led_pattern.h` 后 `self_test.obj` | 仍 23:14:23（未重编） | 更新为新时间戳 |
| `.out` 反汇编中的常量 | `MOV AH, #0x436f`（旧） | `MOV AH, #0xdead` / `MOV AL, #0xbeef`（新） |
| HIL 判定 | PASS（假） | `FAIL H3-selftest (code=1, firmware is in fail-safe)` |

取证手段：`dis2000 <image>` 反汇编后 grep 常量（`grep -i "dead\|beef\|436f"`）。
**二进制镜像里搜不到某个常量，就是它没被编进去** —— 比看构建日志可靠。

## 副作用与注意

- 任何头文件变动都会触发全量重编（本工程可接受）。
- **"gmake 打印了 building file" ≠ 产物真的更新了。** 判据只看
  `.obj`/`.out` 的时间戳与反汇编内容。
- 观察到一次"编译命令执行了但 `.obj` 未更新、且链接也未发生"的情况；
  遇到产物不更新时用 `ccs.ps1 rebuild`（clean + all）兜底。

## 后果

- Makefile 增加 `HEADERS` 变量并在 `.obj` 规则中引用。
- 故障注入实验得以正确完成，REQ-004 负向路径取得真板证据。
