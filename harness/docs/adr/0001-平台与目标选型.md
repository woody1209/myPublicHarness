# ADR 0001 · 平台与目标选型：LAUNCHXL-F280039C + CCS CLI + driverlib，时钟取 INTOSC2

- 状态：已接受
- 日期：2026-10-16
- 决策者：f280039c-harness 项目

## 背景

需要为 AI 生产软件的嵌入式流水线建立 TI C2000 分支，目标为 LAUNCHXL-F280039C
（TMS320F280039C，C28x@120MHz，384KB Flash / 69KB SRAM，板载 XDS110）。
本机已装 CCS 21.0.1 + C28x 编译器 25.11.1.LTS + C2000Ware 26.01.00.00。
参考原型：`C3M3-harness`（Infineon PSOC Control C3M3，只读参考）。

## 决策

1. **平台**：TI C2000 F280039C；工具链只用 CCS 的**命令行组件**（cl2000 / gmake / loadti / xdsdfu），
   不在 IDE 里点按钮构建，保证代理可复现。
2. **固件库**：使用 **driverlib**（SDK 内的 `<C2000Ware>/driverlib/f28003x/driverlib/ccs/Debug/driverlib.lib` + 头文件，
   SDK 绝对路径由 `harness/env/manifest.json` 的 `sdk.c2000ware.root` 提供），
   不用 SysConfig 生成 pin 代码——引脚只有两个 LED，手工集中在 `board_pins.h` 更易评审与追溯。
3. **时钟源**：**INTOSC2 10MHz → IMULT(48)/REFDIV(1)/ODIV(4)/SYSDIV(1) → 120MHz**，
   不用外部晶振；对无外部晶振或晶振未起振的板更鲁棒。
4. **日志**：SCIA → XDS110 虚拟 COM（115200-8N1，TX=GPIO29/RX=GPIO28），替代昂贵的外部串口线。
5. **不在本分支引入 FreeRTOS**：C2000Ware 26.01 的 FreeRTOS `portasm.asm`（development 分支）
   使用 C 风格注释 `/* */`，C28x 汇编器不接受（报 E0002），引入需先补一个前置处理步骤。

## 备选与理由

| 备选 | 落选原因 |
|---|---|
| SysConfig 生成工程（`.syscfg` + board.c） | 黑盒生成物不利于 diff 评审与追溯；本工程引脚极少，手工 YAML-free 更直接 |
| 外部 20MHz 晶振做 PLL 源 | 依赖板上晶振；起振失败会卡在初始化，不利于长期稳定与批量复用该 harness |
| bitfield / 直接寄存器 | 不利于代理产出正确性；driverlib 有显式 API，更符合"禁止硬编码寄存器值"规范 |
| FreeRTOS 版本流水灯 | 引入不必要的 RTOS 依赖，且当前 SDK 的 `portasm.asm` 与工具链存在已知不兼容 |

## 后果

- 时钟策略固定在 `source/board_clock.c`；改用外部晶振属于 **M 级改动**，需写 spec 并更新本 ADR。
- 产物形态：`.out` 由 cl2000 链接产生（ELF/DWARF），可用 `ccs.ps1 size` 报体积，
  用 loadti/DSS 加载；符号表保留，便于 fail-safe 时定位。
- 后续若引入 RTOS 或更多外设，先写 spec（M/L 级），并按 docs/10 的踩坑记录处理 SDK 与工具链差异。
