# ADR 0009 · 门禁必须可失败：有效性判据与 verify.ps1 聚合门

- 状态：已接受
- 日期：2026-10-18
- 决策者：用户（"所有的检查都应有门禁，门禁应有可执行的目标要求约束"）；墨衡起草

## 背景

同一天出现了两份互相矛盾的审计：仓库内的 `harness/docs/81-AIDLC符合性审计.md` 判
"三柱闭环可用、环境不需要修改"，独立复核判"机制成立但证据链有洞"。分歧不在事实，
在**判据**：docs/81 把"门禁跑绿"当作"门禁有效"，而复核问的是"这条门禁能不能红"。

本轮实跑证据（都可复现）：

- `harness/templates/ci/github-actions.yml` 的静态分析以 `cppcheck … || true` 结尾——**永远不会红**；
  文档却写"默认开启"，而仓库根根本没有 workflow 目录。
- `spec.ps1 check` 打印 `CHECK OK`，但对 REQ-003 的 `tests: []` 与正文自认"±2 % 未覆盖"不报错；
  `done` 收口接受无因由的 `waived`。
- HIL 结果有两份真相：`targets/F280039C.json` 写 `status:"pass"`，`projects/<proj>/state.json` 写
  `unavailable`——过期那份还在被引用。
- `run-hil.ps1` 曾把"探针不在"记成"固件坏了"（假 FAIL，ADR 0008 修的是假 PASS，同一类病）。
- AGENTS.md 四条强制路径指向不存在的文件，`.workbuddy/memory/…` 更要求写到本仓库之外
  （与 §6 第 3 条直接冲突）。
- `ccs.ps1 size` 把 C28x 的**字**当**字节**上报，flash 占用减半（违反自家 ADR 0002）。

结论：绿灯不是证据。**能被证据支撑的只有"这条检查在坏输入上确实红过"。**

## 决策

1. **每条门禁必须打印可执行的量化判据**（阈值、单位、来源文件），且判据缺失时按失败处理，
   禁止把"数不清"读成通过。例：体积腿要求 `FLASH/RAM ≤ 90 %`（单位：字，预算取自
   `targets/F280039C.json`）；单测腿要求 `cases > 0 AND failures == 0`，`0 cases` 是红不是绿。
2. **新门禁上线必须做负向自测**：构造一个应红的输入，确认退出码非 0 且消息指出该修的地方，
   然后把样本删掉。本轮已执行的负向自测：`verify.ps1 -MaxFlashPct 2`（体积红）、
   `-MaxTextDeltaWords -1`（增量红）、`-Skip host-test`（未知跳过名 → 用法错误退出 2）、
   违约 manifest 样本（4 处 schema 违约全部被抓出）、
   工程配置样本（`build_config=CPU2_FLASH`/`fpu=fpu64` 两处 enum 违约 +
   把 `paths.host_tests` 临时指向不存在的目录 → `CFG-PATH` 红，随后已还原）、
   `Get-Content -Raw` 不带 `-Encoding` 的 scratch 脚本（`PS-READ-ENCODING` 红，退出 1，样本已删）。
   聚合门本身也在真板上连跑四轮（2026-10-18 09:46 / 10:01 / 10:04 / 10:08），每轮 9 腿全 PASS，
   H5 节拍 197.0 / 195.8 / 196.5 / 195.0 ms——**同一块板同一镜像的散布就有 1.0 %**，
   这正是 ±2 % 不能交给 JTAG peek 裁决的实测理由（见第 9 条）。
3. **跳过 ≠ 通过**：`harness/tools/verify.ps1` 对 `SKIPPED` / `NOT RUN` 打印
   `VERIFY INCOMPLETE` 并退出 1；只有全部相关腿 PASS 才是 `VERIFY OK`（退出 0）。
   省略 `-Hil` 时上板这一腿显示 `NOT RUN`，判词明写"本结论不声称该项"。
4. **DoD 只有一条命令**：`.\harness\tools\verify.ps1`（固件行为改动必须加 `-Hil`）。
   单腿命令仍可独立跑，但"完成"的判据以聚合门为准（AGENTS.md §2 表格是其强制版）。
5. **地图必须可走**：`harness/tools/static-check.ps1` 新增 `DOC-DEAD-ROUTE` 规则，
   扫 AGENTS.md / `harness/docs/**` / `specs/**/*.md` / 工程 README 里的路线，指向不存在的路径即红。
   本轮清出 15 条死路（含 docs/81 自己引用的那条），现为 0。
6. **状态只写一处**：运行时结果（HIL/构建/体积）的唯一真相是 `projects/<proj>/state.json`
   （契约 `harness/schemas/state.schema.json`）与 `harness/tests/on-target/records/`；
   板级卡 `targets/<MPN>.json` 只写硬件事实，`harness/docs/40-烧录与调试手册.md` 的诚实清单
   只写"为什么覆盖不到 + 怎么补"，状态改回指 `specs/<id>/trace.json`。
   HIL 记录文件名按**日期**生成，同一天再跑一次会覆盖当日那份 md（原始 `hil-dss-*`/`hil-sci-*`
   日志按时间戳各自留档）：散文里的数字是引用，权威值只在那份记录里。
7. **契约必须有脚本执行，否则删掉契约**：`harness/schemas/` 现在五份，份份有消费方——
   spec/trace 由 `spec.ps1 check`、state 由 `verify.ps1`、manifest 由 `doctor.ps1` 写后自校验
   （违约写进 `problems` 并退出 1）、project.config 由 `static-check.ps1` 的 config 腿校验
   （schema + 工程名一致 + 每个 `paths.*` 目录存在 + `build_config` 有对应输出目录）。
8. **红线要有网**：`AGENTS.md` §3/§4 的硬件红线（GPIO35–38 复用、裸引脚号、定长 `sprintf`、
   动态内存、裸调工具链）全部落在 `static-check.ps1` 的规则表里（PIN-JTAG-3538 两个形态、
   PIN-BARE-LITERAL、PIN-BARE-PINCFG、FMT-SPRINTF、MEM-DYNAMIC、IO-STDIO、TOOL-BARE-BUILD、
   REF-READONLY-C3M3），工具自身的坑也一样：`PS-READ-ENCODING` 禁止 `-Raw` 读文件不带
   `-Encoding`（本机是 PowerShell 5.1，无 BOM 的 UTF-8 会被按 GBK 解，真相源一旦再序列化
   就把中文写成乱码）。文字规则会被绕过，规则表不会。
9. **无法自动裁的验收必须显式拆条款并 waiver**，禁止靠改数字蒙混：REQ-003 的节拍精度拆成
   ±25 %（HIL halt-free 可裁，门禁 `CADENCE_TOL=0.25`）与 ±2 %（需外部仪器，用户决定延后），
   后者写进 `trace.json` 的 `waiver_reason`，`verified` 只代表前者。**±2 % 至今未被任何门禁证明。**

## 备选与理由

| 备选 | 落选原因 |
|---|---|
| 靠 CI 流水线强制 | 仓库还没接入 GitHub（用户本轮明确"git 先不严管，CI 待后续完善"），runner 上也没有 XDS110，硬件腿必须在本地跑；模板继续留着，但文档必须写"未启用" |
| 把 AGENTS.md 的规范文字写得更细 | 本轮 15 条死路正是"只靠文字"的结果：文字规则不可执行，漂移无人发现 |
| 保持"人工逐条核对" | 不可复现、成本高，且人正是把"跑绿"当成"有效"的那一方 |
| 让 `|| true` 之类的软失败先留着、以后收紧 | 软失败门禁会训练所有人忽略它，且无法区分"没问题"与"没跑成" |

## 后果

- "完成"这个声明现在必须附带一条命令的退出码；代理不能再凭脚本"没报错"自证。
- 负面成本：门禁自身成了被审计对象——每次改判据都要重做负向自测；聚合门跑完需要构建
  与 `cl /analyze`，耗时明显上升（可用 `-Skip` 换速度，但那会留下 `VERIFY INCOMPLETE`，
  不得当作 PASS）。
- 板卡文件不再携带运行结果，历史上引用 `targets` 卡 `hil` 段的文档需要改指 state.json（已改）。
- `harness/docs/81-AIDLC符合性审计.md` 按本判据重写：§4 逐条承载独立评审 10 条发现的处置与状态，
  §5 列出负向自测清单；首轮"环境不需要修改"那句判词已改为"按可证红重判后，需要修改的是 harness 自己"。
- 触发复审：接入 GitHub/Actions 时（模板要补 `static-check` 与 `verify.ps1` job）、
  外部仪器到位时（±2 % 必须变成可执行判据，`waiver_reason` 才能撤销）、
  新增第二个 spec 或换目标板时（判据阈值与预算要重填）。
