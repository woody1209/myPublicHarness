# ADR 0006 · 仿真启动模式（DCON）与 H6 冷启动方式

- 状态：已接受
- 日期：2026-10-17
- 决策者：woodywu

## 背景

HIL 的 H6 要求"测完把板子留在独立运行状态"，早期实现用 `target.reset()` 期望 boot ROM
自己交接给 flash。上板实测：复位后 PC 长期停在 `0x3FB8B9`（boot ROM SCI wait），
halt-free 采样 LED 翻转数 = 0，串口再无输出；而同一镜像一旦把 `PC` 设成 `0x80000`
（入口字 `0x48` = LCR）就立刻正常启动。若不搞清这是固件缺陷、镜像缺陷还是启动机制，
就会把"烧录后板子不跑"的错误结论永久留在 harness 里。

## 决策

1. H6 固定使用 `PC = code_start` + `runAsynch` + `disconnect` 作为**由探针触发的等价冷启动**，
   并保留 `AutoRunToLabelOnRestart=false`（否则 load 后自动跑到 `main`，跳过
   `code_start/wd_disable`，看门狗循环复位）。
2. 不把"`target.reset()` 能进 flash"写成期望，也不为它加绕过逻辑；`hil_test.js` 直接以
   `code_start` 起步，H2 只校验 flash 内容与入口字。
3. **离线 Stand-Alone 引导（断电重上电）不进自动化门禁**，登记在 docs/40"未覆盖项"，
   由人工断电复验；同时 REQ-004 的 fail-safe 故障注入、REQ-003 的 ±2% 精度也一并登记为未覆盖，
   trace.json 相应条目不得写 `verified`（REQ-004 已降为 `pending`）。

## 备选与理由

| 备选 | 落选原因 |
|---|---|
| 用 `target.reset()` 当作独立运行起点 | ROM 在仿真器在线时走 Emulation Boot，仿真引导键无效即落 Wait/SCI 引导，永远不进 flash；把它写进门禁只会产出一个恒假的 FAIL |
| 试图从 DSS 写 OTP/仿真引导键把 Emulation Boot 配成 flash 引导 | OTP 一次性；F28003x 头文件里没有 EMUBKEY/BOOTPIN 的可写定义，等于用不可逆操作去验证一个非缺陷 |
| 用 `xdsdfu` 复位探针制造 POR | 探针固件复位是否切断目标供电未证实，属破坏性未知路径；需要断电验证时应让人工做 |
| 加一条"人工勾选：断电后能跑"的门禁项 | 人工声明不可复现、会随时间失效；登记为未覆盖 + 复验步骤更可审计 |

## 后果

- 正面：H6 结论与机理对齐（RESC bit31 DCON → Emulation Boot → Wait），不再把
  "复位不跑"当固件缺陷追；`targets/F280039C.json.boot_mode` 与 docs/40 记下判读方法
  （看 RESC 解码 + PC 落点 + halt-free 翻转数三件一起看）。
- 负面/需持续承担：**"断电即跑"这一产品级事实在本 harness 中没有可执行证据**；每次交付前
  需要一次人工断电复验（约 10 秒），或在板级测试台引入可控电源后补自动化门禁。
- 触发复审：新增自定义 boot 模式固件（自研 bootloader/IAP）、引入可通过 ERAD/看门狗
  触发非调试复位并能在复位后由 SCI 上报的测试钩子，或搭建可控电源台架。

## 证据

- `harness/tests/on-target/records/diag17-out.log`（复位后 PC 恒 0x3FB8B9、RESC=0xC0000004）
- `harness/tests/on-target/records/diag20-dss.log` + `diag20-com5.log`（2026-10-17：复位释放后
  5s 内 5 个检查点全在 BOOT ROM，halt-free 2.6s 翻转数 0；捕获到的 1272 字节全部是复位前旧运行的尾巴）
- `harness/tools/dss/hil_test.js`（H6 实现）、`harness/docs/40-烧录与调试手册.md`
  （"DSS / HIL 调试经验""未覆盖项"两节）
- 外部佐证：TI C2000 启动章节（无 `-TRST` 的 F28003x 用 RESC.DCON 区分
  Emulation / Stand-Alone Boot；仿真引导键非 0x5A 即进入 Wait 模式），
  e2e.ti.com 帖子 756676 与 501033（同为"CCS 复位卡在 ROM wait、断电重启即正常"）。
