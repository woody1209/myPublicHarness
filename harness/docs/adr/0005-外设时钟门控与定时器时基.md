# ADR 0005 · 外设时钟门控与 CPUTIMER 时基（上板定案）

- 状态：已接受
- 日期：2026-10-17
- 决策者：woodywu（板已连接，由 HIL 门禁实证裁决）

## 背景

REQ-005（SCI 日志）与 REQ-003（200ms 节拍）在主机侧单测与静态审查下都"看起来正确"，
但接上 LAUNCHXL-F280039C 后：串口一个字节不出；HIL H5 报步进 123.6ms / 426ms（不同采样方式
给出不同数值）。同一时间 driverlib 调用与链接脚本都无报错，说明缺陷在**硅片假设**层面，
而这两条假设此前只写在文档里、没有被任何门禁钉住。

## 决策

1. 固件在使用任何外设之前必须显式 `SysCtl_enablePeripheral(SYSCTL_PERIPH_CLK_x)`；
   本工程 `board_clock_init()` 固定使能 `SYSCTL_PERIPH_CLK_SCIA`（CPUSYS PCLKCR7 bit0，
   字地址 0x5D330 = 基址 0x5D300 + `SYSCTL_O_PCLKCR7` 0x30）。
2. HIL 的 H3 增加门禁：读 0x5D330，bit0=0 即以 `H3-sciclk` 失败——把"静默丢写"变成可执行断言。
3. CPUTIMER0 周期回到 `BOARD_SYSCLK_FREQ_HZ / tick_hz`（时基 = SYSCLK，TPR=0 时不减 LSPCLK）；
   同时 `board_timer_init()` 设 `CPUTimer_setEmulationMode(CPUTIMER0_BASE, CPUTIMER_EMULATIONMODE_RUNFREE)`。
4. **时序测量必须在核心保持运行的状态下做**（halt-free 内存 peek）。禁止用"halt—读—run"
   循环判定节拍，因为 TIF 是单个标志位，halt 期间的多次溢出在恢复后只累加一次。

## 备选与理由

| 备选 | 落选原因 |
|---|---|
| 依赖 device.h / TI 启动代码顺带打开 SCI 时钟 | 纯 driverlib 路径不会执行 `InitSysCtrl()`；且"写被静默丢弃"没有任何错误码，靠人眼永远查不出 |
| 绕过 driverlib 直接 `EALLOW; CpuSysRegs.PCLKCR7.bit.SCI_A=1` | AGENTS 分层规则要求外设操作走 driverlib；`SysCtl_enablePeripheral()` 就是官方内联封装 |
| 把定时器周期按 SYSCLK/4 算（曾被误判为"实测如此"） | 该结论来自 halt 采样：PRD=30000 在无停机探针下实测 51.4ms 翻转 = 257µs/tick，时基就是 120MHz SYSCLK；/4 会让流水灯真的快 4 倍 |
| 用 `while(!(TIF))`+忙等近似计时 | REQ-003 明确禁止软件忙等近似；且忙等无法区分被 halt 压缩的时间 |

## 后果

- 正面：REQ-005 从"0 字节"到 banner + 每 5s 心跳（115200-8N1，LBAUD=0x1F 实测有效）；
  REQ-003 由 HIL H5 给出同日四轮均值（192.5 / 193.5 / 194.5 / 195.1ms，各 12 次跳变）的实测证据；两条硅片事实进入
  `targets/F280039C.json` 与 docs/40，后续移植新外设不会再踩。
- 需持续承担：新增外设时**必须**同时加时钟使能（评审清单加一条）；HIL 若改回 halt 采样，
  节拍结论立即失真；`.TI.ramfunc`/看门狗顺序仍是前置条件（ADR 0003），时钟使能排在时钟配置之后。
- 触发复审：更换目标板/芯片系列（PCLKCR 偏移不同）、引入 RTOS 或改用 eCAP/PWM 时基、
  或引入逻辑分析仪做 ±2% 级测量（届时 halt-free 的采样分辨率不再是限制）。
