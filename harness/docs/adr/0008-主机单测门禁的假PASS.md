# ADR 0008 · 主机单测门禁的假 PASS（PowerShell 返回值污染）

- 状态：已接受
- 日期：2026-10-18
- 决策者：woodywu（由故障注入实验暴露）

## 背景

在故障注入状态下（自检参考常量被改坏），主机单测的实际结果是：

```
cases: 20, failures: 2 -> FAIL
```

直接运行 `test_runner.exe` 的退出码也是 **1**。但 `run-host-tests.ps1` 却输出：

```
all host unit tests passed     （退出码 0）
```

即门禁把**红灯报成绿灯**。这使整个 TDD 支柱失去意义：门禁永远说"通过"。

## 根因：函数的输出流污染返回值

`Invoke-MsvcFallback` 内部用 `Write-Output` 打印提示信息，且 `& cl.exe` 的输出
未重定向。在 PowerShell 中，**函数写入输出流的一切都会成为它的返回值**：

```powershell
if (Invoke-MsvcFallback) { ... }   # 收到的不是 [bool]，而是
                                   # @("...building...", <exe 输出...>, $false)
```

**非空数组在布尔上下文中恒为真** —— 于是 `if (...)` 永远成立，无论测试红绿都走
"passed" 分支。

顺带解释了一个表象：我加的诊断 `Write-Output` 行"消失"了 —— 它被 `if` 当作返回值
吃掉了，根本没到控制台。

## 决策

1. **函数内的提示信息一律用 `Write-Host`**，不进返回值流，确保函数只返回一个布尔。
2. **`& cl.exe` 的输出先捕获再 `Write-Host` 转发**（未重定向的原生调用同样会污染返回值）。
3. **判定双保险**：既看退出码，也解析 runner 自己打印的判定行
   （`cases: N, failures: M -> PASS/FAIL`）——后者不受退出码传递问题影响。

```powershell
$runOut = & $exe 2>&1
$runExit = $LASTEXITCODE
$runText = ($runOut | Out-String)
if ($runText -match 'failures:\s*(\d+)') {
    if ([int]$Matches[1] -gt 0) { $runExit = 1 }
}
elseif ($runText -match '\-\>\s*FAIL') { $runExit = 1 }
...
return ($runExit -eq 0)
```

## 备选方案（落选）

- **`Start-Process -PassThru` 取 `ExitCode`**：本机不可用。环境中同时存在
  `HTTPS_PROXY` 与 `https_proxy`（仅大小写不同），`Start-Process` 直接抛
  `ArgumentException: 已添加项。字典中的关键字:"HTTPS_PROXY"...`。
- **只依赖 `$LASTEXITCODE`**：已被证明不可靠，且无法解释本次假 PASS。

## 证据

| 阶段 | 脚本输出 | 真实结果 |
|---|---|---|
| 修复前（坏常量） | `all host unit tests passed` (exit 0) | `failures: 2 -> FAIL` (exit 1) |
| 修复后（坏常量） | `host unit tests FAILED (msvc fallback)` (exit 1) | 一致 ✅ |
| 修复后（还原） | `all host unit tests passed` (exit 0) | `failures: 0 -> PASS` ✅ |

## 通用教训（适用于本仓库所有 .ps1 工具）

**PowerShell 函数里若要返回布尔/标量，内部就不能用 `Write-Output` 输出信息，
也不能让原生命令的输出"漏"到输出流。** 否则调用方的 `if (...)` 会被数组劫持。
写 PowerShell 门禁脚本时，这一条等同于 C 里的"返回值与副作用分离"。

## 后果

- `harness/tools/run-host-tests.ps1` 已按上述三点修复并验证。
- 门禁恢复可信：坏常量判红、还原后判绿。
