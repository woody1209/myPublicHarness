# 50 · CI 与版本管理

## 持续集成（**模板，尚未启用**）

真相先说清楚：`harness/templates/ci/github-actions.yml` 只是模板，仓库根没有
`<repo>/.github/workflows/`，所以**当前没有任何门禁在 CI 里自动跑**。
用户 2026-10-18 决定：Git 基线与 GitHub 接入本轮不管，先把本地门禁做实。
因此本项目"每次变更强制"的载体是**一条本地命令**（见下节），不是流水线。

模板里三个 job 的设计意图（启用后才生效）：

1. `host-tests`（ubuntu）：cmake + gcc + ctest，跑纯逻辑单测。
2. `static-analysis`：cppcheck 扫 `projects/launchxl-f280039c-led-chaser/source`，
   `--enable=warning,style --error-exitcode=1`（**没有 `|| true`**——不能失败的检查不是门禁），
   产出 XML 归档（`if: always()`，失败也要留证据）。
3. `spec-check`（windows）：`.\harness\tools\spec.ps1 check`。
4. `firmware-build`（windows）：装 CCS + C2000Ware 后跑 `.\harness\tools\ccs.ps1 build`
   （CPU1_FLASH + CPU1_RAM 双配置）。默认关闭——由仓库变量 `RUN_FW_BUILD=true` 打开
   （Windows runner 成本与工具安装复杂度高）。

启用清单（接 GitHub 时按此补齐，别照抄旧文档）：把模板复制进
`<repo>/.github/workflows/`；补 `harness/tools/static-check.ps1` 这一 job（本地已有、
模板里还没有）；HIL 见最后一节。

## 本地等价命令（当前真正强制执行的那一条）

```powershell
.\harness\tools\verify.ps1          # 环境→静态检查→单测→spec→state→构建→体积→体积增量
.\harness\tools\verify.ps1 -Hil     # 固件行为改动必须加 -Hil（板上真跑，判据见 AGENTS.md §2 第 9 行）
```

退出码即 DoD 结论：`VERIFY OK` / `VERIFY INCOMPLETE` / `VERIFY FAIL` 都是退出码，
跳过某腿 = 该判据未被证明，按失败处理（ADR 0009）。单腿命令仍可单独跑：
`doctor.ps1` / `static-check.ps1` / `run-host-tests.ps1` / `spec.ps1 check` /
`ccs.ps1 build|size` / `run-hil.ps1`。

## 版本管理

- Git：工程根目录初始化（`.gitignore` 已排除 build/、IDE 文件）。**当前状态：未初始化提交，
  待用户接入 GitHub（AGENTS.md §6：commit 只在用户要求时创建）。**
- 提交粒度：一个逻辑变更一个提交；S/M/L 分级见 `harness/docs/20-AI生产规范.md`。
- 发布：语义化版本写 `source/app_version.h`；发布提交打 tag `vX.Y.Z`，
  message 必须含最终 `.text/.data` 尺寸（`ccs.ps1 size`）。
- 依赖升级（C2000Ware / 编译器）：重跑 `doctor.ps1`，更新 `harness/docs/10-环境总览.md`
  的已验证环境表，附上回归结论（`verify.ps1` 全绿 + 双配置构建 + 单测）。
